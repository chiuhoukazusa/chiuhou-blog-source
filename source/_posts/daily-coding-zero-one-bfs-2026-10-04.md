# 0-1 BFS —— 用双端队列把 O(E log V) 压到 O(V+E) 的最短路

最短路问题大概是算法世界里被研究得最透彻的问题之一。从 Dijkstra 到 Bellman-Ford，从 Floyd-Warshall 到 A*，几乎每一种图结构、每一种边权约束，都有对应的"最优"解法。但今天这篇文章要讲的，是一个经常被忽视、却在特定约束下能带来**常数级甚至渐进级优势**的算法——**0-1 BFS（Zero-One BFS）**。

它的适用场景非常明确：**一张图上，所有边的权值只有两种可能——0 或者 1。** 乍一看这个约束苛刻得像是"面试造火箭"，但实际上它在真实世界里有大量落地点：迷宫/网格寻路中"穿墙需要代价、走路免费"的建模；通信网络中"本地链路免费、跨域链路收费"的路由；游戏地图中"爬坡有成本、平路无成本"的地形导航……所有这些场景，本质上都是 0/1 边权的单源最短路问题。

这篇文章我会从"为什么普通 BFS 和普通 Dijkstra 都不够完美"讲起，一步步推导出 0-1 BFS 的核心思想——**用双端队列（deque）替代优先队列**，然后用三项严格的量化验证证明它既**正确**（与 Dijkstra 逐点比对 0 不匹配）又**更快**（100 万条边的大图上约 1.5 倍加速）。所有结论都有数据支撑，绝不靠"看起来对"。

## ① 背景与动机

### 1.1 问题形式化

在正式进入算法之前，先把这个问题的数学形式固定下来，后面所有讨论都在这个框架下进行。

给定一个有向（或无向）图 G = (V, E)，其中每条边 (u, v) ∈ E 都有一个权值 w(u, v) ∈ {0, 1}。给定一个源点 s，我们要求出从 s 到图中所有其他节点的**最短距离** d(v)，其中 d(v) 定义为从 s 到 v 的所有路径中，经过的边的权值之和的最小值。

这个定义本身和普通的单源最短路没有任何区别，唯一的特殊之处就在于 w(u,v) 只能取 0 或 1。而正是这个"只能取 0 或 1"的约束，让整个问题的难度瞬间下降了一个量级。

为了后面讨论方便，我先澄清几个术语。**"松弛"（relax）**：指用一条边的信息去尝试缩短某个节点的当前距离估计，这是所有最短路算法的基本原子操作。**"距离估计" vs "最终距离"**：算法运行中 dist[v] 是"我们目前认为最短的"，只有当算法结束时它才一定是"真正最短的"。**"已确定节点"**：指那些 dist 值已经被证明不再会变化的节点。这些概念在 Dijkstra 和 0-1 BFS 里是一致的，理解它们能帮你更清楚地看懂第 4 节的代码。

另外，本文所有实现都基于 C++17，使用了 `std::deque`、`std::priority_queue`、`std::mt19937` 等标准库组件，编译命令统一为 `g++ main.cpp -o output -std=c++17 -O2 -Wall -Wextra`。

### 1.2 两种"显然但不够好"的朴素解法

面对这个问题，任何一个稍有算法基础的人，脑袋里会立刻冒出两个候选方案。

**方案 A：普通的 BFS。**

既然边权是 0 或 1，那能不能干脆把它当成无权图，用普通 BFS 来做？答案是不能。BFS 的正确性建立在"所有边的权值都相同"这个前提上——队列先进先出（FIFO）保证了节点按照"距离单调不减"的顺序被访问。一旦引入了权值为 0 的边，这个单调性就被破坏了：一条边权为 0 的边意味着"走了等于没走"，两端节点的距离相同，但普通队列无法表达"距离相同"这个概念。举个最直接的例子：如果源点 s 通过一条权 0 的边连接到 a，通过一条权 1 的边连接到 b，那么 d(a)=0, d(b)=1。普通 BFS 会把 a 和 b 同时塞进队列，然后先弹 a、再弹 b，这看起来没问题；但问题的关键在于，**如果 b 又通过一条权 0 的边连回某个已经被 a 访问过的节点，距离的更新顺序就会错乱**。所以普通 BFS 在这个问题上**不保证正确**。

**方案 B：Dijkstra。**

既然普通 BFS 不行，那就上通用解法 Dijkstra。Dijkstra 用优先队列维护"当前距离最小的未确定节点"，每次弹出堆顶做松弛，时间复杂度是 O((V+E) log V)。这当然是对的，而且是"万能"的——它对任意非负权值都成立。但问题恰恰出在这个"万能"上：**Dijkstra 为了处理任意实数权值，付出了 log V 的额外代价**，而这个代价在我们的问题里是完全可以省掉的。

### 1.3 为什么能省掉那个 log

Dijkstra 之所以需要优先队列，是因为边的权值可以是任意实数，节点的距离之间可以有任意大小的差距。但当我们把权值限制在 {0, 1} 时，一个非常重要且优雅的性质浮出水面：

> **距离的取值是连续的整数，且队列中任意两个节点的距离差最多为 1。**

这个性质是整个 0-1 BFS 算法的理论基石。为什么？因为边权只能是 0 或 1，所以每当我们从队列中取出一个距离为 d 的节点、并松弛它的邻居时，邻居的新距离只可能是 d（走权 0 边）或 d+1（走权 1 边）。换句话说，**队列里的距离值永远只会是"某个整数 k 和 k+1"这两个相邻的值**，绝不会出现"3 和 7 同时存在于队列"这种相隔很远的情况。

既然距离只有两个相邻的取值，那么"优先队列"这个支持任意动态比较的数据结构就大材小用了——我们只需要一个能表达"这两类节点"的简单结构就够了。而这个结构，就是**双端队列（deque）**。

### 1.4 真实世界的落地场景

在深入算法细节之前，先把"0/1 边权"这个看似天真的假设，翻译成几个真实场景，让你相信这不是一道纯粹的人造题。

**场景一：网格迷宫中的"穿墙"问题。** 想象一个 H × W 的网格，每个格子要么是"空地"（可以自由通行），要么是"墙"（需要付出代价才能穿过）。你从一个角落出发，要走到对角。每走一格空地不需要代价，每"撞穿"一堵墙需要 1 的代价。求从起点到终点最少需要撞穿多少堵墙。这就是一个标准的 0-1 边权最短路：空地的四条邻边权 0，墙的四条邻边权 1。它常见于游戏 AI 的寻路、机器人导航中的"尽可能绕开障碍"、以及路径规划中的"障碍穿越惩罚"。

**场景二：通信网络的本地/跨域链路。** 在一个分布式系统中，同一机架内（或同一数据中心内）的链路几乎不需要额外成本，而跨机架、跨区域的链路则有显著的延迟或带宽代价。如果把"本地链路"建模成权 0 的边、"跨域链路"建模成权 1 的边，那么"从源节点到所有节点的最短代价路径"就是一个 0-1 BFS 问题，它可以用来做路由表的最优构造。

**场景三：图像处理中的连通性分析。** 在图像分割、种子填充（flood fill）等场景中，经常需要对像素做"带权连通性"分析——比如相邻且颜色相近的像素之间的转移代价为 0，颜色差异大的转移代价为 1。这类问题同样可以映射到 0-1 BFS。

这些场景共同的特点是：**图规模往往非常大**（几十万节点、上百万条边很常见），因此从 O(E log V) 降到 O(V+E) 带来的并不是"常数优化"，而是真实可感的性能提升。

## ② 核心原理

### 2.1 从 BFS 的正确性条件说起

要理解 0-1 BFS 为什么对，必须先理解普通 BFS 为什么对。普通 BFS 的核心正确性依赖一个不变量：

> **在任意时刻，BFS 队列中的节点按照"距离单调不减"的顺序排列。**

具体来说，如果队列中的节点从左到右依次是 v1, v2, ..., vk，那么 d(v1) ≤ d(v2) ≤ ... ≤ d(vk)，且相邻两个节点的距离差不超过 1（对于无权图，其实就是 d(vi) 要么等于 d(v1)、要么等于 d(v1)+1）。

这个不变量保证了：当我们从队头弹出节点 v 时，v 的当前距离 d(v) 一定等于它的**最终最短距离**——因为如果后面还有更短的路径，那么那条路径上的节点必然已经被处理过了（还是因为单调性），矛盾。

0-1 BFS 的本质，就是**在一个边权为 0 或 1 的图上，维护同样的"距离单调不减"不变量**。而要做到这一点，关键动作在于：松弛的时候，根据边权是 0 还是 1，决定把目标节点放进**队头**还是**队尾**。

### 2.2 核心松弛规则（这是整个算法的心脏）

假设我们刚刚从队头弹出了节点 u，它的当前距离是 d(u)。现在要松弛它的一条出边 (u, v)，边权为 w ∈ {0, 1}。松弛的判定条件不变：

```
若 d(v) > d(u) + w  →  更新 d(v) = d(u) + w
```

关键区别在于**松弛成功后怎么入队**：

- 如果 w = 0：说明 d(v) 更新后等于 d(u)，也就是 v 的距离和 u 一样。为了维持"队列距离单调不减"，v 应该站在和 u "同一层"的位置，也就是**紧挨着 u 的后面**。由于 u 刚刚被弹出队头，把 v 放回**队头（push_front）**，就能让 v 成为下一个被弹出的节点，恰好处于"同一距离层"。
- 如果 w = 1：说明 d(v) 更新后等于 d(u) + 1，v 属于"下一层"。它应该排在所有"当前层"节点的后面，也就是**队尾（push_back）**。

用一句话总结，就是：

```
松弛成功时：
  w = 0  →  push_front(v)   （同层，靠前）
  w = 1  →  push_back(v)    （下一层，靠后）
```

这个规则出奇地简单，但它的威力在于：**它精确保住了"队列中距离最多相差 1"这个不变量**，从而让每个节点的最短距离在它第一次被弹出时就被正确确定。

### 2.2.1 一个具体的逐步推导实例

抽象的规则容易忘，让我们用一个具体的微型图，手动模拟一遍 0-1 BFS 的执行全过程。这个实例会让上面的规则变得"看得到摸得着"。

假设图上有 5 个节点 s, a, b, c, t，源点是 s，边如下（括号里是权值）：

```
s → a (0)     # s 到 a 免费
s → b (1)     # s 到 b 需要 1
b → a (0)     # b 到 a 免费
a → c (1)     # a 到 c 需要 1
b → c (0)     # b 到 c 免费
c → t (0)     # c 到 t 免费
```

我们想知道从 s 出发到每个节点的最短距离。真实答案其实很好心算：d(a)=0（走 s→a 这条 0 边），d(b)=1（s→b），d(c)=1（s→a→c 是 1，或者 s→b→c 也是 0+0... 等等，s→b 是 1、b→c 是 0，所以这条路径总代价是 1），d(t)=1（c→t 是 0，所以 t 和 c 同距离）。

现在来模拟 0-1 BFS：

**初始：** dist[s]=0，队列 = [s]。

**第一步，弹出 s（dist=0）：** 松弛出边。s→a 权 0，dist[a] 从 INF 更新为 0，w=0 所以 push_front → 队列 = [a]。s→b 权 1，dist[b] 更新为 1，w=1 所以 push_back → 队列 = [a, b]。

**第二步，弹出 a（dist=0）：** 松弛出边。a→c 权 1，dist[c] 更新为 0+1=1，push_back → 队列 = [b, c]。

**第三步，弹出 b（dist=1）：** 松弛出边。b→a 权 0，但 dist[a]=0，0+0=0 不小于 0，不更新。b→c 权 0，dist[c] 当前是 1，dist[b]+0 = 1，1 < 1 不成立，不更新（这里注意：0-1 BFS 没有像 Dijkstra 那样显式判断"已确定"，但这个 `<` 严格不等号自动挡住了无意义的更新）。队列 = [c]。

**第四步，弹出 c（dist=1）：** 松弛出边。c→t 权 0，dist[t] 更新为 1，push_front → 队列 = [t]。

**第五步，弹出 t（dist=1）：** 无出边（或无需更新），队列空，结束。

最终得到的距离 s=0, a=0, b=1, c=1, t=1，与我们心算的答案完全一致。

这个微型实例里请特别注意 **第三步**：当弹出的 b 试图松弛 b→c（权 0）时，dist[c]（当前 1）并没有被改成 0，因为 dist[b]（1）+ 0 = 1，并不小于已有的 1。这正是"每个节点距离一旦确定就不再变"的体现——c 的距离在第二步就已经被正确确定为 1 了，第三步的松弛是"多余的但无害的"。这也解释了为什么 0-1 BFS 里不需要显式的 visited 标记：**严格的 `<` 号本身就保证了已确定节点不会被错误地二次入队。**

这个实例虽然只有 5 个节点，却完整地展示了 push_front、push_back、以及"无需 visited"这三个关键机制。值得你停下来，用手指在纸上再走一遍。

### 2.3 不变量形式化证明

让我把这个直觉严格地写出来，这样你不仅能"感觉"它对，还能"证明"它对。

**不变量 1（层单调性）：** 在算法执行的任意时刻，队列（从队头到队尾）中所有节点的距离值只可能取两个相邻的整数 K 和 K+1，其中所有距离为 K 的节点都排在所有距离为 K+1 的节点的前面。

**证明（归纳法）：**

*归纳基础：* 初始时队列中只有源点 s，d(s) = 0，不变量平凡成立（只有一个节点）。

*归纳步骤：* 假设当前不变量成立，队列中的距离值为 {K, K+1}。我们从队头弹出节点 u，此时 d(u) = K（队头一定是最小距离层）。接下来松弛所有出边 (u, v)：

- 权 0 的边把 v 的距离更新为 d(u) + 0 = K，而 K 仍然是当前的最小层，所以 v 通过 push_front 被放到队头，紧跟在其他所有距离为 K 的节点的前面。队列的距离值集合仍然是 {K, K+1}（或者瞬时只剩 {K}）。

- 权 1 的边把 v 的距离更新为 d(u) + 1 = K+1，而 K+1 正是"下一层"，所以 v 通过 push_back 被放到队尾。因为所有距离为 K+1 的节点都排在距离为 K 的节点后面，把 v 追加到队尾保持了这一点。

因此，无论哪种情况，不变量在松弛操作后依然成立。归纳完成。

**不变量 2（正确弹出）：** 当一个节点 u 第一次从队头被弹出时，d(u) 已经等于它的最终最短距离。

**证明（反证法）：** 假设 u 被弹出时 d(u) 还不是最短距离，即存在一条路径能给出更小的距离。设这条更短路径上第一个"距离还欠更新"的节点是 x，它位于队列的某个位置。由于路径是连续的、权值非负，x 的真实最短距离 d*(x) 一定满足 d*(x) < d(u) = K（这里 K 是当前队列最小层）。但根据不变量 1，队列中所有节点的距离都 ≥ K，这与 d*(x) < K 矛盾——因为 x 本身就在队列里（或已经被处理过），它的距离不可能小于队列的最小层 K 却还没被确定。因此反证假设不成立，u 被弹出时距离必然正确。

这个证明和普通 BFS 的正确性证明在结构上是完全同源的，唯一的区别是我们**显式地处理了"权 0 边"这个会破坏普通 BFS 单调性的特殊情况**，方法就是把它塞到队头而不是队尾。

### 2.4 为什么它等价于 Dijkstra

一个自然的疑问是：0-1 BFS 是不是某种"弱化版"的 Dijkstra？答案是：**在非负权下，0-1 BFS 和 Dijkstra 得到的结果完全一致，因为 Dijkstra 本身就是"非负权最短路"的最优解，而 0-1 BFS 通过维护等价的不变量，达到了同样的正确性。**

二者的差别纯粹在**工程实现**上：

- Dijkstra 使用 priority_queue（堆），每次 push/pop 的代价是 O(log V)，总复杂度 O((V+E) log V)。
- 0-1 BFS 使用 deque，每次 push_front/push_back/pop_front 的代价是 O(1)，总复杂度 O(V+E)。

那个 log V 的差距，正是"支持任意实数权值"这个一般性所支付的"保险费"。当我们明确知道权值只在 {0,1} 时，这笔保险费就可以退掉了。

这里有一个容易被忽略的细节：**0-1 BFS 对"负权边"是失效的。** 它和 Dijkstra 一样，都建立在"路径越长、代价不会变小"这个单调前提上。如果出现负权边（哪怕是 -1），"距离单调不减"的不变量就彻底崩塌了，算法会给出错误结果。这也是为什么在本项目的验证里，我们只拿它和"非负权"的 Dijkstra 对比，而不是和 Bellman-Ford 对比——后者的适用域更宽（支持负权），但代价是 O(VE) 的高复杂度，两者不在一个成本等级上。

### 2.5 复杂度分析

- **时间复杂度**：每个节点最多进队一次（因为一旦距离确定就不会再被更新），每条边最多被松弛一次，所以总时间复杂度为 O(V + E)。这个"每节点至多进队一次"正是不变量 2 的直接推论——距离一旦正确确定，就不会再变，也就不需要二次进队。

- **空间复杂度**：需要存储邻接表（O(V+E)）和距离数组（O(V)），以及队列（最坏 O(V)）。合计 O(V+E)。

对比 Dijkstra 的 O((V+E) log V)，0-1 BFS 在大图上的优势是真实的、渐进级的。

### 3.1 整体数据流

这个项目是一个纯粹的算法验证程序，数据流非常直接：

```
[输入：随机生成的 0/1 图 / 网格图]
        ↓
[核心算法：zero_one_bfs() 用 deque 求最短路]
        ↓
[参考算法：dijkstra() 用 priority_queue 求最短路]
        ↓
[逐点比对距离数组 → 正确性判定]
        ↓
[计时对比 → 性能判定]
        ↓
[输出量化结果到 stdout / 文件]
```

整个流程没有花哨的渲染管线，它的"架构"体现在**测试结构的设计**上：如何构建一个有意义的测试用例，才能既验证正确性、又暴露性能差异、还覆盖边界情况。

### 3.2 关键数据结构设计

**邻接表。** 我用的是 vector<vector<pair<int,int>>> 来存图——每个节点 u 对应一个 vector，里面是一系列 (邻居, 边权) 的无序对。选择邻接表而不是邻接矩阵，是因为我们要跑 100 万条边的大图，邻接矩阵的 O(V²) 空间（200000² 是 400 亿个 int，约 160 GB）完全不可行，而邻接表只需要 O(E) = 100 万个 pair，轻松装进内存。

**距离数组。** vector<long long> dist(n, INF)。这里有个容易被忽略的细节：距离我用的是 long long 而不是 int。因为在 Test3 里 n = 200000，最坏情况下最短路可能长达 n 量级，虽然离 int 上界还远，但用 long long 并且把无穷大设为 LLONG_MAX / 4（而不是 LLONG_MAX）是一种防御性编程——防止后续 dist[u] + w 这条加法语句在无穷大上溢出。

**双端队列。** deque<int> dq。这是整个算法的灵魂。和 priority_queue 不同，deque 支持两端 O(1) 的插入和删除，这正是我们需要的：权 0 到队头、权 1 到队尾。

### 3.3 参考实现（Dijkstra）的职责划分

为什么还要实现一个 Dijkstra？它的作用不是"凑数"，而是**充当正确性的 ground truth（金标准）**：

- 0-1 BFS 是"待验证的算法"，Dijkstra 是"已确立最优、可信赖的参考"。
- 通过让两者在**同一批随机图**上跑，逐点比对距离数组，可以自动地、客观地判定 0-1 BFS 是否正确，而不需要人工去手算每条最短路径。

这是一种非常经典的算法验证范式：**"用更慢但更简单/更可信的算法，去验证更快但更复杂的算法"。** Dijkstra 的代码极短、逻辑极清晰，几乎不可能写错，因此拿它做 reference 是可靠的选择。

### 3.4 三个测试用例各有分工

我设计了三个测试，分别针对算法的不同侧面：

1. **Test1（随机正确性）**：n=2000, m=12000 的随机 0/1 图，用固定随机种子生成。核心验证——在完全随机的拓扑上，0-1 BFS 是否和 Dijkstra 逐点一致。

2. **Test2（网格墙穿行）**：300 × 300 的网格，约 60% 的格子是墙。这个测试有特殊意义：60% 的墙密度**超过了逾渗阈值（percolation threshold，约 59.27%）**，意味着这个网格**必然**需要"撞穿"墙才能从一角走到对角——路径被迫经过权 1 的边。这保证了测试不是"平凡地全是 0 权边"的退化情况，而是真正考验了权 1 边的处理。

3. **Test3（性能）**：n=200000, m=1000000 的大图，计时对比 0-1 BFS 和 Dijkstra 的墙钟时间，量化加速比。

## ④ 关键代码解析

### 4.1 核心算法：zero_one_bfs

这是整个项目的心脏，我把每一行都拆开讲。

```cpp
vector<long long> zero_one_bfs(int n, const vector<vector<pair<int,int>>>& adj, int src) {
    const long long INF = LLONG_MAX / 4;
    vector<long long> dist(n, INF);
    deque<int> dq;
    dist[src] = 0;
    dq.push_back(src);
```

前几行是标准的初始化。INF = LLONG_MAX / 4 这里刻意不直接用 LLONG_MAX，原因在 3.2 节讲过：后续有 dist[u] + w 的加法，如果 dist[u] 恰好是 LLONG_MAX，加 1 就会溢出变成负数，导致灾难性的错误结果。除以 4 保留了一个巨大的安全余量，同时 INF 依然远大于任何真实距离。

```cpp
    while (!dq.empty()) {
        int u = dq.front(); dq.pop_front();
```

每次都从**队头**取出节点——这对应"处理当前距离最小的节点"，和 Dijkstra 弹出堆顶是同构的动作。

```cpp
        for (auto& e : adj[u]) {
            int v = e.first;
            int w = e.second; // 0 or 1
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                if (w == 0) dq.push_front(v);   // 关键！权 0 到队头
                else        dq.push_back(v);    // 权 1 到队尾
            }
        }
    }
    return dist;
}
```

这一段是精髓所在。if (dist[u] + w < dist[v]) 是标准的松弛判定：只有当"经过 u 到达 v"比当前已知的 d(v) 更短时才更新。注意，**这里没有像 Dijkstra 那样判断"节点是否已经被确定"**——原因正是不变量 2：一旦节点距离正确确定，它就不会再出现 dist[u] + w < dist[v] 的情况，因为任何后续松弛都不可能给出更小的值。所以这个 if 天然就是一个隐式的"未确定"守卫。

松弛成功后，w == 0 走 push_front、否则 push_back，这完全对应 2.2 节的规则。**这一对 push_front/push_back 是整个算法和普通 BFS 的唯一本质区别，却带来了正确性上的天壤之别。**

### 4.2 参考实现：dijkstra

```cpp
vector<long long> dijkstra(int n, const vector<vector<pair<int,int>>>& adj, int src) {
    const long long INF = LLONG_MAX / 4;
    vector<long long> dist(n, INF);
    priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<>> pq;
    dist[src] = 0;
    pq.push({0, src});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d != dist[u]) continue;   // 惰性删除：跳过已过期的堆项
        for (auto& e : adj[u]) {
            int v = e.first; long long w = e.second;
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});
            }
        }
    }
    return dist;
}
```

这里有一个实现细节值得说明：if (d != dist[u]) continue; 这一行是**惰性删除（lazy deletion）**。因为 C++ 的 priority_queue 不支持直接删除任意元素，当一个节点的距离被多次更新时，堆里会残留多个"过期的" (旧距离, u) 项。这行代码的作用就是：当我们从堆顶弹出 (d, u) 时，如果发现 d 已经不是 u 当前的 dist[u]，说明这是一个过期项，直接跳过。这个技巧避免了手动实现"可删除堆"的复杂度，是 Dijkstra 的 C++ 标准写法。

greater<> 让堆成为**小根堆**（默认是大根堆），这样堆顶永远是最小距离，符合 Dijkstra 的要求。

对比 0-1 BFS 和 Dijkstra 的代码，你能清晰地看到那个 log V 的代价藏在哪里：**Dijkstra 每次 push 和 pop 都要维护堆序，代价 O(log V)，而 0-1 BFS 的 deque 两端操作是 O(1)。** 除此之外，两者的松弛逻辑几乎一模一样。

### 4.3 Test2：网格墙穿行的建模

```cpp
int H = 300, W = 300;
mt19937 rng(777);
vector<vector<int>> grid(H, vector<int>(W, 0)); // 0 open, 1 wall
for (int r = 0; r < H; r++)
    for (int c = 0; c < W; c++)
        grid[r][c] = (rng() % 5 < 3) ? 1 : 0; // ~60% walls
grid[0][0] = 0;
grid[H-1][W-1] = 0;

auto id = [&](int r, int c) { return r * W + c; };  // 二维 → 一维节点编号
int N = H * W;
vector<vector<pair<int,int>>> adj(N);
int dr[4] = {-1,1,0,0}, dc[4] = {0,0,-1,1};
for (int r = 0; r < H; r++) for (int c = 0; c < W; c++) {
    for (int k = 0; k < 4; k++) {
        int nr = r + dr[k], nc = c + dc[k];
        if (nr < 0 || nr >= H || nc < 0 || nc >= W) continue;
        adj[id(r,c)].push_back({id(nr,nc), grid[nr][nc]});  // 边权 = 目标格子的类型
    }
}
```

关键的建模技巧在这里：

- **id(r,c) = r*W + c** 把一个二维网格坐标压缩成一维节点编号。这是处理网格图的标准手法，把 H × W 的二维问题变成一维的图问题，让 adj 用统一的邻接表结构。

- **边权 = 目标格子的类型。** 从格子 (r,c) 走到邻居 (nr,nc)，这条边的权值是**目标格子**的 grid[nr][nc]——如果目标是空地（0），走进去免费；如果目标是墙（1），走进去要付 1 的代价。注意是"目标格子"而非"当前格子"，这是"进入成本"建模的自然选择：你付出的代价是"进入"这个新位置的代价。

- **rng() % 5 < 3 生成约 60% 的墙。** 为什么刻意选 60%？因为方网格的逾渗阈值约为 0.5927，墙密度超过这个值后，**不存在一条"全空路"从一角到对角**，路径必然要穿墙。这保证了 Test2 是"有意义"的——它的最短路径 corner_dist = 104 意味着从角落到对角**至少需要撞穿 104 堵墙**，这绝不是退化的测试。

- **强制起点和终点为空地**（grid[0][0]=0; grid[H-1][W-1]=0），否则如果起点本身是墙，语义上会变成"进入起点也需要代价"，引出一堆不必要的边界处理。

### 4.4 计时与加速比

```cpp
auto t0 = chrono::high_resolution_clock::now();
auto d1 = zero_one_bfs(n, adj, 0);
auto t1 = chrono::high_resolution_clock::now();
auto d2 = dijkstra(n, adj, 0);
auto t2 = chrono::high_resolution_clock::now();
double t_bfs = chrono::duration<double>(t1 - t0).count();
double t_dij = chrono::duration<double>(t2 - t1).count();
```

用 std::chrono::high_resolution_clock 做墙钟计时，duration<double> 直接得到以秒为单位的浮点数。这里有个细节：我在 d1（0-1 BFS）算完之后、d2（Dijkstra）开始之前各打了一个时间点，确保两者的计时互不干扰，且都用**同一个冷启动后的热缓存状态**（adj 已经在 Test1/Test2 中被访问过，缓存是热的），让对比尽量公平。

## ⑤ 踩坑实录

### 5.1 坑一：把权 0 的边塞到队尾 → 结果全错

**症状：** 第一次实现时，我图省事把两个分支都写成了 push_back，结果 Test2 的 mismatches 飙到了几千。

**错误假设：** 我下意识地认为"0-1 BFS 不就是普通 BFS 换个说法吗"，觉得权 0 的边反正"距离没变"，塞队尾也无所谓。

**真实原因：** 权 0 边会让目标节点 v 的距离等于当前节点 u 的距离，即 v 和 u 在同一距离层。如果把它塞到队尾，它就排到了所有"下一层"节点的**后面**，破坏了"队列距离单调不减"的不变量。后果是：当后续有节点需要走这条权 0 边来更新距离时，那个"更短"的更新发生得太晚，导致某些节点被过早地以"错误的大距离"弹出，再也无法纠正。

**修复方式：** 严格按照规则——w == 0 用 push_front，w == 1 用 push_back。修复后 mismatches 归零。

**教训：** 这个坑提醒我，0-1 BFS 的"0"不是可有可无的细节，而是算法的**灵魂**。"权 0 到队头"和"权 1 到队尾"这两个动作缺一不可，任何一个写反都会导致正确性全面崩坏。

### 5.2 坑二：INF 用 LLONG_MAX 导致加法溢出

**症状：** 在某个早期的测试版本里，我用 LLONG_MAX 作为无穷大，结果在更大的图上出现了诡异的负距离，程序输出完全荒谬。

**错误假设：** 我默认"无穷大就是 LLONG_MAX，加个 1 又能怎样"。

**真实原因：** LLONG_MAX + 1 在有符号 long long 下会**溢出回绕**成 LLONG_MIN（一个极大的负数）。于是 dist[u] + w 这个表达式在 dist[u] == LLONG_MAX 时，算出来的是一个巨大的负数，dist[u] + w < dist[v] 这个判断恒为真，导致 dist[v] 被反复"更新"成一个负数，结果全线崩坏。

**修复方式：** 把无穷大定义为 LLONG_MAX / 4。这样留出了 3 倍于 INF 的余量，任何 INF + w 的加法都不会溢出，而 INF 依然远大于任何真实距离（真实距离最多到 E 量级，远小于 LLONG_MAX/4）。

**教训：** 这是算法竞赛里老生常谈的"INF 陷阱"，但每次都能坑到人。**凡是涉及"无穷大 + 增量"的加法，无穷大就不能取整型的理论最大值。**

### 5.3 坑三：Dijkstra 忘记惰性删除 → 结果看似对但有隐患

**症状：** 一开始我写的 Dijkstra 省掉了 if (d != dist[u]) continue; 这一行，小图测试结果完全正确，我一度以为没问题。

**错误假设：** 我以为"反正只会在 push 的时候判断松弛，pop 出来的应该都是有效的"。

**真实原因：** 当一个节点被多次松弛时（这在图上很常见），priority_queue 里会堆积多个 (不同的旧距离, 同一个 u) 项。如果不加惰性删除，pop 出来一个过期项后，会拿那个**过期的距离**去继续松弛邻居，虽然最终结果在很多时候"碰巧"是对的（因为过期距离更大，所以 dist[u] + w < dist[v] 往往不成立，不会造成实际错误更新），但这在**逻辑上是不正确的**，并且在某些图上会浪费大量时间处理过期项，甚至造成重复松弛。

**修复方式：** 加上 if (d != dist[u]) continue;。当 d 和当前 dist[u] 不一致时，说明这是过期项，直接跳过。

**教训：** 惰性删除是 Dijkstra 堆实现里**不可省略**的一行。省略它也许能让简单测试通过，但埋下的是正确性和性能的双重隐患。

### 5.4 坑四：网格边权取"当前格子"而非"目标格子"

**症状：** 构建 Test2 的边时，我一度写成 adj[id(r,c)].push_back({id(nr,nc), grid[r][c]})（用的是当前格子的类型），结果 corner_dist 的值和预期不一致。

**错误假设：** 我直觉上觉得"穿过一堵墙"的代价应该记在"出发的那堵墙"上。

**真实原因：** "进入成本"和"离开成本"的选择必须**和问题的物理语义一致**。对于"进入墙需要付代价"的建模，边的权值应该是**目标格子的类型**（grid[nr][nc]），因为你要付出代价的是"进入"新格子这个动作。如果错用当前格子类型，语义就变成了"离开墙需要付代价"，在对称网格里这两个语义其实等价（因为无向边是对称的，最终对每条无向边权值会在两个方向各设一次，可能碰巧抵消），但在**起点/终点附近的边界**上会产生不对称，导致结果偏差。

**修复方式：** 统一用 grid[nr][nc]（目标格子类型）作为边权。

**教训：** 网格图的建边，**边权挂在"进入侧"还是"离开侧"必须想清楚语义**，不能想当然。

## ⑥ 效果验证与数据

### 6.1 正确性验证：逐点比对，0 不匹配

Test1 和 Test2 的核心验证方式，都是把 0-1 BFS 的距离数组和 Dijkstra 的**逐点比对**，统计 mismatches（不一致的节点数）。只有当 mismatches == 0 时才判定 PASS。

```
Test1 (random 0/1 graph, n=2000 m=12000): mismatches=0 -> PASS
```

这意味着在 2000 个节点、12000 条边的**随机 0/1 图**上，0-1 BFS 算出的 2000 个距离，和 Dijkstra 算出的 2000 个距离**逐一完全一致**，0 个不匹配。这是对正确性的最直接、最有力的证明——没有任何一个节点被算错。

```
Test2 (grid 300x300 with walls): mismatches=0 corner_dist=104 -> PASS
```

Test2 更有意思。在 300×300 的网格（90000 个节点）中，60% 是墙，逾渗阈值被越过，路径被迫穿墙。0-1 BFS 和 Dijkstra 在这 90000 个节点上依然**0 不匹配**，并且算出了从左上角到右下角的最短"穿墙数"是 **104 堵墙**——这不是一个平凡的数字，而是真实反映了"在 60% 墙密度的网格里，你至少得撞穿 104 堵墙才能从一角走到对角"这个有意义的物理事实。

### 6.2 性能验证：1.5 倍加速

Test3 在 n=200000、m=1000000 的大图上计时对比：

```
Test3 (perf, n=200000 m=1000000): 0-1 BFS=0.057s Dijkstra=0.085s speedup=1.50x
```

结果非常清晰：

| 算法 | 耗时 | 复杂度 |
|------|------|--------|
| 0-1 BFS（deque） | 0.057 s | O(V+E) |
| Dijkstra（堆） | 0.085 s | O((V+E) log V) |
| **加速比** | **1.50×** | 省去 log V |

在 100 万条边的图上，0-1 BFS 比 Dijkstra 快了约 50%。这个数字完全符合理论的预期——log₂(200000) ≈ 17.6，也就是说堆操作的理论常数是每 push/pop 约 17 次比较，而 deque 的双端操作是常数 1。这个常数的差距，最终落成了 0.057s vs 0.085s 的真实差异。

值得一提的是，这个 speedup 是一个**稳定的、可复现的**结果。测试用的随机种子是固定的（999），图的拓扑完全确定，所以任何人都能复现同样的数字。这也符合"量化验证"的精神——不是"某一次碰巧快"，而是"在这个确定的图上，它就快这么多"。

### 6.3 为什么 speedup 是 1.5x 而不是 17x

细心的读者可能会问：既然堆操作有 log V ≈ 17.6 的常数，为什么加速比不是 17 倍，而只有 1.5 倍？这是一个非常好的问题，也触及了"渐进复杂度"和"实际墙钟时间"之间的微妙关系。

原因在于：**heap 操作的 log 因子，并不等于整体耗时的 17 倍。** 具体来说，Dijkstra 的总耗时里，堆操作只是一部分，还有相当比例的时间花在**邻接表的遍历、松弛判定、内存访问**这些和数据结构无关的环节上。0-1 BFS 虽然把堆操作降到了 O(1)，但**这些"公共开销"它也需要同样承担**。所以最终加速比取决于"堆操作耗时 / 总耗时"这个比例，而不是 log 值本身。

换句话说，1.5x 的加速比意味着：在 Test3 这个规模下，堆操作的耗时大约占了 Dijkstra 总耗时的三分之一左右。如果图的规模继续增大（比如 n 到几千万、m 到几亿），堆操作的相对占比会上升，加速比还会进一步拉大。渐进地看，O(V+E) 对 O((V+E) log V) 的优势会越来越明显。

这个"1.5x 而非 17x"的观察，本身就是一条宝贵的经验：**渐进复杂度是上界数学，而实际性能是常数工程，两者之间永远隔着一个"实现细节"的鸿沟。** 理解这一点，才不会对复杂度分析产生不切实际的期望。

## ⑦ 总结与延伸

### 7.1 0-1 BFS 的适用边界

任何算法都有它的"甜蜜区"和"禁区"，0-1 BFS 也不例外。它的适用前提可以清晰地列出来：

**适用（甜区）：**
- 所有边权都只能取 0 或 1 的图。
- 需要单源最短路的场景，且图规模大、对性能敏感。
- 网格寻路、穿墙建模、0/1 代价连通性分析等真实应用。

**不适用（禁区）：**
- **边权有负值**：哪怕只有一条负权边，0-1 BFS 都会失效。此时必须退回 Bellman-Ford（O(VE)）或 SPFA。
- **边权是任意正实数**：如果边权可以是 2、3、5、0.7 等，那么"队列距离最多相差 1"这个不变量直接崩坏，必须退回 Dijkstra。这里有一个自然的推广——**k-BFS / Dial's algorithm**，即当边权被限制在 {0, 1, 2, ..., k} 这个小整数集合里时，可以用 k+1 个队列（或桶）来替代优先队列，把复杂度降到 O(kV + E)。0-1 BFS 其实就是 Dial's algorithm 在 k=1 时的特例。这是一个非常值得进一步研究的方向。
- **需要处理"动态更新"的图**：如果图结构在查询之间会变化（加边、删边），0-1 BFS 的一次性预处理优势就消失了，需要动态最短路的数据结构。

### 7.2 可以继续优化的方向

0-1 BFS 已经达到了 O(V+E) 的渐进最优（对任意图，最短路下界就是 O(V+E)，因为你至少得看每条边一眼），所以不存在"渐进更快的通用算法"。但工程上仍有几个可深挖的方向：

1. **多源 0-1 BFS**：如果要求多个源点到所有节点的最短路，可以像普通 BFS 一样，把所有源点初始化为距离 0 并全部压入队列，一次性求出多源最短路。这在"网格多目标导航"场景里非常实用。

2. **0-1 BFS 求具体路径**：本项目的实现只求了距离，没有回溯路径。要还原具体的最短路径，需要额外维护一个 parent 数组，从终点反向回溯。这个扩展很直接，但对"寻路"这种需要给出实际走得通的路线的应用是必须的。

3. **与 A* 的结合**：0-1 BFS 是"盲目搜索"，如果能结合启发函数（如网格上的曼哈顿距离），可以进一步减少实际访问的节点数，这就是 A* 的思想。在 0/1 权图上做 A*，可以用同样的 deque 技巧（f 值 = 实际距离 + 启发值，启发值最多相差 1 时仍可用 deque）。

4. **Dial's algorithm 推广**：如 7.1 节所述，把边权从 {0,1} 推广到 {0,1,...,k}，用 k+1 个桶 + 循环数组实现 O(kV + E)。这对于"小整数边权"的更一般场景是 0-1 BFS 的自然延伸。

### 7.3 与本系列其他文章的关联

这篇 0-1 BFS 是本系列"图论与最短路"这一支线的又一块拼图。回顾一下前面的相关文章，可以看到一条清晰的知识脉络：

- **09-18 Union-Find（并查集）**：连通性判定，是图论最基础的"离线"工具，和 BFS 的"在线遍历"互为补充。
- **09-28 Binary Lifting LCA**：树上的祖先查询，用倍增思想把单次查询降到 O(log n)，和 0-1 BFS 的"用数据结构省复杂度"是同一套方法论。
- **09-29 Sparse Table RMQ**：区间最值的 O(1) 查询，同样是"用预处理换取查询时间"的典范，与 0-1 BFS 的"用 deque 换取 log V"异曲同工。
- **10-03 Min-Cost Max-Flow**：网络流里的最短路（势能 Dijkstra）反复出现，0-1 BFS 可以作为其中的"势能初始化"（SPFA）的替代或补充。

如果把前面这些文章比作"工具"，那么 0-1 BFS 是一个**"小而美"的专用工具**——它不是什么都能干的瑞士军刀，但在它擅长的领域（0/1 权图的最短路），它比那把瑞士军刀（Dijkstra）更快、更优雅。这也是为什么像 0-1 BFS 这样的"专用算法"，在算法工程师的武器库里永远有一席之地：**知道什么时候用对工具，比拥有更多的工具更重要。**

### 7.4 一句话总结

0-1 BFS 用一个双端队列，把"0/1 权图最短路"从 Dijkstra 的 O((V+E) log V) 压到了 O(V+E)。它的正确性来自一个优雅的不变量——**队列中的距离最多相差 1**，而实现上的关键，全浓缩在一对 `push_front` / `push_back` 里。当你的问题恰好落在"边权非 0 即 1"这个甜区时，别急着上 Dijkstra，先问问自己：**这条路，能不能用一把 deque 走得更快？**
