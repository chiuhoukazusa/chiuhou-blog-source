# 每日编程实践：自然三次样条插值（Natural Cubic Spline Interpolation）

> 今天的每日编程实践主题是 **数值方法中的自然三次样条插值（Natural Cubic Spline Interpolation）**。我们通过解一个三对角线性方程组（使用 Thomas 算法）来构造一条 **二阶连续（C² 连续）** 的分段三次多项式曲线，使其精确通过所有给定数据点，同时避免全局多项式插值在等距节点下著名的 **Runge 现象（龙格震荡）**。本篇文章会完整推导数学原理、展示实现架构、逐行解析核心代码、如实记录踩坑过程，并用**解析函数误差、收敛阶、精确性重建**三项量化指标严格验证结果的正确性。

---

## ① 背景与动机

在科学计算、计算机辅助设计（CAD）、游戏开发、动画、金融曲线拟合等众多领域，我们经常面临这样的问题：**给定一组离散的采样点 `(x_i, y_i)`，如何构造一条光滑曲线穿过它们？** 这就是经典的**插值（Interpolation）**问题。

### 为什么要关心插值？

插值的本质是"用有限的信息重建连续的函数"。设想一个工程师拿到了一组传感器读出来的 100 个温度采样点，他希望绘制一条连续的温度变化曲线；或者一个动画师每隔 0.1 秒设置了一个角色关节角度关键帧，他希望角色在关键帧之间平滑运动，而不是一帧一帧地"跳变"。

如果直接用**线性插值**——即把相邻两点用直线连起来——虽然简单，但曲线在数据点处会出现明显的"折角"（导数不连续），看起来是一条锯齿状的多段线。这在需要求导（比如计算速度、加速度）的下游场景中会带来灾难性后果：导数处处不连续，甚至在某些点上压根无法定义。

于是人们自然想到：**用更高阶的多项式**来获得更平滑的曲线。

### 全局多项式插值的陷阱：Runge 现象

最"朴素"的高阶方案是构造一个**全局 n-1 次多项式**穿过所有 n 个点（Lagrange 插值、Newton 插值等）。在理论上有著名的 **Weierstrass 逼近定理** 保证：任何连续函数都能被多项式一致逼近。

然而实践给出了沉重的教训。1901 年，德国数学家 **Carl Runge** 发现：对看似无害的函数

```
f(x) = 1 / (1 + 25x²)   ,   x ∈ [-1, 1]
```

在区间上取**等距节点**，随着节点数增多，插值多项式在区间两端会产生**剧烈振荡**，误差反而越来越**大**，完全不收敛到原函数。这就是著名的 **Runge 现象（龙格现象 / Runge's phenomenon）**。

这一现象的根本原因在于：高次多项式是"全局刚性"的——它在某一点附近的行为会强制影响整个定义域。一旦某个区域拟合不好，误差就会"传染"到全区间，并表现为振荡。

### 工业界的真实解法：分段低次多项式

工业界（包括 CAD 软件的曲线工具、游戏引擎的动画曲线编辑器、金融插值库）早已抛弃了"全局高次多项式"这条路，转而采用**分段低次多项式**的方案：**把定义域切成若干段，每一段用一个低阶多项式，并在段与段的交界处施加连续性约束**。

分段方案的关键优势在于**误差是局部的**：某一小段的拟合误差不会传播到其它段。这正是 Runge 现象的解药。

在这条路线上，**三次样条（Cubic Spline）** 是最经典、最实用的选择，原因有三：

1. **三次是"足够光滑"的最低阶数**：三次多项式拥有连续的二次导数，能保证曲线在人眼和物理意义上都足够平滑（不存在曲率突变导致的视觉或力学不自然）。
2. **三次是"局部灵活"与"光滑"的平衡点**：阶数再低（一次）会折角，阶数再高又容易在段内产生不必要的振荡（类似 Runge 现象在单段内的复发）。
3. **三次样条有高效的线性求解算法**：构造自然三次样条等价于解一个**三对角线性方程组**，可以用 Thomas 算法在 `O(n)` 时间内解决，计算代价极小。

### 本文目标

本文将完整实现一个**自然三次样条插值器**：

- 从给定数据点出发，构造满足 **C² 连续**（函数值、一阶导、二阶导都在节点处连续）的分段三次多项式；
- 使用**自然边界条件**（Natural Boundary Condition），即两端的二阶导数为零；
- 用 **Thomas 算法**高效求解三对角系统；
- 通过三项**量化验证**证明正确性：与 `sin(x)`、`e^x` 等解析函数的误差对比、收敛阶测量、以及线性函数/节点精确重现；
- 并与全局多项式插值做**头对头对比**，直观展示样条如何以 87 倍优势避免 Runge 现象。

## ② 核心原理

本节我们从零推导三次样条的完整数学构造。请读者注意：**每一个公式我们都会给出直觉解释**，而不仅仅是"背结论"。

### 2.1 分段三次多项式的设置

假设我们有 `n` 个数据点：

```
(x_0, y_0), (x_1, y_1), ..., (x_{n-1}, y_{n-1})   其中 x_0 < x_1 < ... < x_{n-1}
```

我们希望在每相邻两点之间构造一个三次多项式。整个样条 `S(x)` 由 `n-1` 段三次多项式拼接而成，第 `i` 段定义在 `[x_i, x_{i+1}]` 上。

对于第 `i` 段，我们采用**局部参数化**：引入局部变量 `t = x - x_i ∈ [0, h_i]`，其中 `h_i = x_{i+1} - x_i` 是第 `i` 段的区间长度。第 `i` 段多项式写为

```
S_i(t) = a_i + b_i·t + c_i·t² + d_i·t³
```

这样每个段有 4 个未知系数 `a_i, b_i, c_i, d_i`，总共 `n-1` 段，共 `4(n-1)` 个未知数。

**直觉**：用局部变量 `t` 而非全局 `x`，是为了让每一段的系数只在本地有意义，数值上也更稳定（避免了大坐标带来的量级差异）。

### 2.2 约束条件

我们需要列出足够的方程来确定这些系数。

**（1）节点处函数值连续（插值条件）**

每一段在端点处必须精确等于给定数据点。这给出：

```
S_i(0)   = y_i         （左端点）
S_i(h_i) = y_{i+1}     （右端点）
```

共 `2(n-1)` 个方程。

**直觉**：这是"插值"最基本的要求——曲线必须穿过所有已知点。没有这条，就不叫插值了。

**（2）一阶导数连续（C¹ 连续）**

在内部节点 `x_i`（`i = 1, ..., n-2`）处，左段与右段的一阶导数必须相等：

```
S_{i-1}'(h_{i-1}) = S_i'(0)
```

共 `n-2` 个方程。

**直觉**：保证曲线不会在节点处"折角"。任何导数不连续的点，在物理上对应速度突变，视觉上对应尖锐的转折。

**（3）二阶导数连续（C² 连续）**

在内部节点处，二阶导数也必须相等：

```
S_{i-1}''(h_{i-1}) = S_i''(0)
```

共 `n-2` 个方程。

**直觉**：保证"曲率"连续，曲线在节点处不会出现"加速度突变"。这正是三次样条之所以平滑的核心，比一阶连续（如二次样条）更进一层。

### 2.3 边界条件：从欠定到定解

现在数一下方程总数：

```
插值条件:        2(n-1)
一阶导数连续:     (n-2)
二阶导数连续:     (n-2)
---------------------------------
总计:          4n - 6 个方程
```

但未知数有 `4(n-1) = 4n - 4` 个。**方程比未知数少 2 个**，系统欠定，还需要 **2 个边界条件** 才能唯一确定样条。

常见的边界条件有三种：

1. **自然边界（Natural）**：`S''(x_0) = 0` 且 `S''(x_{n-1}) = 0`，即两端二阶导数为零。
2. **固定/夹紧边界（Clamped）**：`S'(x_0) = f'(x_0)` 且 `S'(x_{n-1}) = f'(x_{n-1})`，即给定两端一阶导数（通常是真实函数导数的真值）。
3. **非节点（Not-a-knot）**：要求前两段和后两段的三阶导数连续，等价于让"第 2 个和第 n-2 个节点不真正成为分段点"。

本文选择**自然边界条件**，它是默认、最常见的选择，优点是**无需任何额外的导数信息**（在只有离散采样点、不知道真实函数导数时，这是唯一可行的方案）。

**直觉**：自然边界"假设"曲线在两端是"放松"的——像一个两端自由的细长弹性木条（spline 一词本就源于造船用的柔性木条 spline），被钉在数据点上后自然弯曲，两端不施加额外力矩。二阶导数为零意味着两端"没有弯曲力矩"。

> ⚠️ **最重要的理论提醒**：自然边界条件导致样条的全局收敛阶为 **O(h²)**（而非夹紧边界下的 O(h⁴)）。原因在于：自然边界强行让两端二阶导数为零，而当真实函数的二阶导数在端点不为零时，会引入一个 O(h²) 级别的边界误差。这个误差会向内部传播。本文后面会用一个实验精确验证这一点。

### 2.4 关键技巧：以二阶导数为未知数

直接解 `4n-4` 个未知数会得到一个（几乎）稠密的线性系统，代价高。经典的三次样条构造法利用了一个巧妙的技巧：**用节点处的二阶导数 `M_i = S''(x_i)` 作为"中介未知数"**。

之所以选择二阶导数，是因为**三次多项式的二阶导数是线性的**。具体地，在第 `i` 段内，`S_i''(x)` 是一条直线，从 `M_i` 线性过渡到 `M_{i+1}`：

```
S_i''(x) = M_i · (x_{i+1} - x)/h_i  +  M_{i+1} · (x - x_i)/h_i
```

**直觉**：这是整段推导的"神来之笔"。三次多项式的一阶导是二次函数，二阶导是一次函数（直线）。一条直线完全由两个端点值 `M_i, M_{i+1}` 确定。因此，只要我们知道每个节点的二阶导数值 `M_i`，通过**两次积分**就能把整段三次多项式完全重建出来。

### 2.5 两次积分重建系数

对 `S_i''(x)` 做一次积分（利用 C¹ 连续条件消去积分常数），再对得到的 `S_i'(x)` 做一次积分（利用插值条件消去积分常数），最终得到用 `M_i, M_{i+1}` 表达的四个系数：

```
a_i = y_i
b_i = (y_{i+1} - y_i)/h_i  -  h_i·(2M_i + M_{i+1})/6
c_i = M_i / 2
d_i = (M_{i+1} - M_i) / (6·h_i)
```

**逐项直觉解释**：

- **`a_i = y_i`**：当 `t = 0` 时 `S_i = a_i`，左端点必须等于 `y_i`，因此 `a_i` 就是左端点函数值，最简单的一条。
- **`c_i = M_i/2`**：二次项系数对应的是该段左端点的二阶导数的一半。因为对 `S_i(t) = a_i + b_i t + c_i t² + d_i t³` 求二阶导得 `S_i''(t) = 2c_i + 6d_i·t`，在 `t=0` 处 `S_i''(0) = 2c_i = M_i`，所以 `c_i = M_i/2`。
- **`d_i = (M_{i+1} - M_i)/(6h_i)`**：三次项系数刻画二阶导数在该段内"变化的速度"。因为二阶导是线性的，其斜率为 `(M_{i+1} - M_i)/h_i`，而 `S_i''(t) = 2c_i + 6d_i·t` 对 `t` 求导得 `6d_i`，所以 `6d_i = (M_{i+1}-M_i)/h_i`，即 `d_i = (M_{i+1} - M_i)/(6h_i)`。
- **`b_i`（最复杂的一项）**：它由两部分组成。第一项 `(y_{i+1}-y_i)/h_i` 是"平均斜率"（线性插值的斜率）；第二项 `-h_i(2M_i + M_{i+1})/6` 是"曲率修正项"，它把二阶导数的影响"折回去"调整一次项，使得插值条件 `S_i(h_i) = y_{i+1}` 能精确满足。

### 2.6 导出三对角线性系统

目前 `M_i` 还是未知的。要确定它们，我们利用**内部节点处一阶导数连续（C¹ 连续）** 这一尚未用过的条件。

将 `S_i'(x)` 的表达式代入 `S_{i-1}'(h_{i-1}) = S_i'(0)`，经过整理（这里省略冗长的代数，但每一步都只是代入和合并同类项），得到对每个内部节点 `i = 1, ..., n-2` 的方程：

```
h_{i-1}·M_{i-1}  +  2(h_{i-1} + h_i)·M_i  +  h_i·M_{i+1}
   =  6 · [ (y_{i+1} - y_i)/h_i  -  (y_i - y_{i-1})/h_{i-1} ]
```

**这个式子的直觉**（非常重要）：

- **左边**是相邻三个节点二阶导数 `M_{i-1}, M_i, M_{i+1}` 的**加权组合**。权重 `h_{i-1}`、`2(h_{i-1}+h_i)`、`h_i` 是相邻区间长度，体现了"曲线弯曲受左右邻居影响"的物理直觉——两侧区间越长，影响越大。
- **右边**是相邻两段的**平均斜率之差乘以 6**。`(y_{i+1}-y_i)/h_i` 是右边一段的平均斜率，`(y_i-y_{i-1})/h_{i-1}` 是左边一段的平均斜率。**两者之差**衡量了曲线在节点 `i` 处的"斜率突变程度"。如果所有点都在一条直线上，则左右斜率相等，右边为 0，导致 `M_i = 0`，这是对的（直线二阶导数为零）。

### 2.7 组装成三对角矩阵

结合自然边界条件 `M_0 = 0` 和 `M_{n-1} = 0`，我们得到一个关于 `M = [M_0, M_1, ..., M_{n-1}]^T` 的线性方程组：

```
[ 1      0                            ] [M_0   ]   [ 0        ]
[ h_0  2(h_0+h_1)  h_1                ] [M_1   ]   [ 6(...)   ]
[      h_1    2(h_1+h_2)  h_2         ] [M_2   ] = [ 6(...)   ]
[              ...                    ] [ ...  ]   [ ...      ]
[                        h_{n-2}   1  ] [M_{n-1}]   [ 0        ]
```

这是一个**三对角矩阵**：只有主对角线、上下两条次对角线非零，其余全零。

**为什么这是好消息**：三对角方程组可以用 **Thomas 算法（追赶法）** 在 `O(n)` 时间和 `O(n)` 空间内精确求解，而通用高斯消元需要 `O(n³)`。这是三次样条如此高效的根本原因。

### 2.8 Thomas 算法（追赶法）

Thomas 算法是专门针对三对角系统的高斯消元特化版本。设系统为：

```
a_i · M_{i-1}  +  b_i · M_i  +  c_i · M_{i+1}  =  d_i
```

其中 `a_0 = 0` 且 `c_{n-1} = 0`（边界处没有"越界"项）。

**第一步：前向消去（Forward Sweep）**

从 `i = 1` 到 `n-1`：

```
m    = a_i / b_{i-1}
b_i  = b_i - m · c_{i-1}
d_i  = d_i - m · d_{i-1}
```

**直觉**：把第 `i` 行的 `a_i`（次对角线元素）"消掉"，通过减去上一行的一个倍数。`m` 就是这个倍数，它使得消元后 `a_i` 变为 0。

**第二步：回代（Back Substitution）**

从 `i = n-1` 到 `0`：

```
M_{n-1} = d_{n-1} / b_{n-1}
M_i     = (d_i - c_i · M_{i+1}) / b_i
```

**直觉**：消元完成后，最后一行的系数只剩 `b_{n-1}`，可以直接求出 `M_{n-1}`；然后从后往前，每个 `M_i` 都可以用已知的 `M_{i+1}` 求出。

Thomas 算法的总操作数是 `O(n)`，且数值稳定（前提是矩阵对角线占优，三次样条的三对角系统满足这一点，因为 `2(h_{i-1}+h_i) > h_{i-1} + h_i`）。

### 2.9 收敛阶分析（为什么是 O(h²) 而非 O(h⁴)）

这是本文最值得记住的理论点之一。

对于**夹紧（clamped）**三次样条，当真实函数 `f` 充分光滑时，误差满足

```
||S - f||_∞ ≤ (5/384)·||f^(4)||_∞·h^4
```

即 **O(h⁴) 收敛**。

但对于**自然（natural）**三次样条，由于自然边界条件 `S''(x_0) = S''(x_{n-1}) = 0` 通常**不等于**真实函数的二阶导数 `f''(x_0)` 和 `f''(x_{n-1})`，会在边界处引入一个 `O(h²)` 的误差，且该误差会传播到整个区间，导致全局收敛阶降为 **O(h²)**。

**直觉**：自然边界是一种"错误"的边界假设（除非真实函数恰好两端二阶导数为零）。这个边界处的"失配"以 O(h²) 的量级污染整个解。而夹紧边界因为使用了正确的导数信息，能把误差压到 O(h⁴)。

本文后面会用实验**实证**这个结论：对 `e^x` 在 `[0,1]` 上，用 4/8/16 个节点测得的收敛阶约为 **2.0**，恰好吻合理论。

### 2.10 与其它方案对比

| 方案 | 平滑性 | 是否 Runge 震荡 | 复杂度 | 收敛阶（光滑函数） |
|------|--------|----------------|--------|---------------------|
| 线性插值 | C⁰ | 无 | O(n) | O(h²) |
| 全局多项式(Lagrange) | C^∞ | **严重** | O(n²) | 可能不收敛（Runge） |
| 二次样条 | C¹ | 无 | O(n) | O(h³) |
| **自然三次样条** | **C²** | **无** | O(n) | O(h²) |
| 夹紧三次样条 | C² | 无 | O(n) | O(h⁴) |

可以看到，自然三次样条以 **O(n) 的低成本** 换来了 **C² 平滑性 + 无 Runge 震荡**，是"性价比"极高的选择。

## ③ 实现架构

### 3.1 整体数据流

本项目的实现分为清晰的五个模块，数据从输入一路流到验证：

```
数据点 (x_i, y_i)
      │
      ▼
[1] 构建三对角系统  ──►  求区间长度 h_i + 右侧 6(斜率差)
      │
      ▼
[2] Thomas 算法求解  ──►  得到节点二阶导数 M_i
      │
      ▼
[3] 重建每段系数    ──►  a_i, b_i, c_i, d_i
      │
      ▼
[4] eval(x) 求值     ──►  二分定位分段 + 局部多项式计算
      │
      ▼
[5] 量化验证         ──►  对比解析函数，输出 max-err/RMSE/收敛阶
```

### 3.2 关键数据结构设计

核心数据结构是 `CubicSpline` 结构体，存储了四个长度均为 `n-1` 的系数数组：

```cpp
struct CubicSpline {
    std::vector<double> xs;   // 节点横坐标（长度 n）
    std::vector<double> a, b, c, d;  // 每段系数（长度 n-1）
};
```

**设计理由**：

1. **存 `xs` 而非隐含等距假设**：支持**非等距节点**，这是真实场景的普遍需求（采样点往往不均匀）。
2. **每段系数独立成数组**：求值时只需读取对应段的 `a[i]/b[i]/c[i]/d[i]`，缓存友好，且避免用结构体数组带来的对齐填充浪费。
3. **局部参数化段多项式 `S_i(t) = a_i + b_i t + c_i t² + d_i t³`**：`t = x - x_i ∈ [0, h_i]`，求值时数值更稳定。

### 3.3 模块职责划分

| 模块 | 职责 | 关键点 |
|------|------|--------|
| `thomasSolve()` | 解三对角系统 | 纯函数，输入 `a/b/c/d`，输出 `M` |
| `CubicSpline::build()` | 从数据点构造样条 | 组装系统 + 调用 Thomas + 重建系数 |
| `CubicSpline::eval()` | 求值 | 二分定位分段，`O(log n)` |
| `LagrangeInterp` | 全局多项式插值（对照用） | 用于演示 Runge 现象 |
| `quantify()` | 误差量化 | 密集采样计算 max-err/RMSE/均值 |

### 3.4 为什么选择这些设计

- **`thomasSolve` 独立出来**：Thomas 算法是通用工具，独立成函数便于复用和单独测试。
- **求值用 `upper_bound` 二分**：`std::upper_bound` 是标准库的二分查找，返回第一个大于 `x` 的位置，减 1 即得所在分段，`O(log n)` 而非朴素线性扫描的 `O(n)`。
- **对照实验用独立的 `LagrangeInterp` 结构体**：保持主逻辑干净，对照算法不影响样条实现。

## ④ 关键代码解析

本节**完整内嵌**核心代码，并逐行解释"为什么这样写"。

### 4.1 Thomas 算法

```cpp
// 三对角线性方程组求解（Thomas 算法 / 追赶法）
// 求解 a[i]*x[i-1] + b[i]*x[i] + c[i]*x[i+1] = d[i]
std::vector<double> thomasSolve(const std::vector<double>& a,
                                const std::vector<double>& b,
                                const std::vector<double>& c,
                                const std::vector<double>& d) {
    int n = (int)d.size();
    // 注意：必须拷贝 b，因为前向消去会原地修改对角线
    std::vector<double> bp = b, cp = c, dp = d;
    std::vector<double> x(n);

    // ---- 前向消去（Forward Sweep） ----
    for (int i = 1; i < n; i++) {
        double m = a[i] / bp[i - 1];   // 消元倍数
        bp[i] -= m * cp[i - 1];        // 消去次对角线，更新主对角线
        dp[i] -= m * dp[i - 1];        // 同步更新右侧
    }

    // ---- 回代（Back Substitution） ----
    x[n - 1] = dp[n - 1] / bp[n - 1];  // 最后一行只有一个未知数
    for (int i = n - 2; i >= 0; i--) {
        x[i] = (dp[i] - cp[i] * x[i + 1]) / bp[i];
    }
    return x;
}
```

**为什么要拷贝 `b` 和 `c`？** 因为 `b` 和 `c` 是以 `const&` 传入的，而前向消去需要**原地修改** `bp[i]` 和后续用到的 `cp[i-1]`。如果不拷贝直接修改形参，会因为 `const` 修饰而编译失败（这是本文踩坑实录里记录的第一个 Bug）。拷贝一份 `bp = b`、`cp = c`、`dp = d` 既保留了传入参数不被污染，又允许原地消元。

**为什么第一个循环从 `i = 1` 开始？** 因为 `a[0]` 在自然边界条件下是 0（第 0 行没有次对角线项），不需要消元。消元从第 1 行开始，逐个消去每行的 `a[i]`。

**为什么回代从 `n-1` 往前？** 前向消元的结果是一个上三角矩阵（次对角线全被消成 0），最后一行只剩 `bp[n-1]·x[n-1] = dp[n-1]`，可以直接解出 `x[n-1]`，然后依次向前代入。

**`m = a[i] / bp[i-1]` 会不会除零？** 对于三次样条的三对角系统，对角线满足严格占优：`2(h_{i-1}+h_i) > h_{i-1} + h_i`，因此 `bp` 在消元过程中始终保持非零，Thomas 算法数值稳定。

### 4.2 构建三对角系统

```cpp
void build(const std::vector<double>& X, const std::vector<double>& Y) {
    int n = (int)X.size();
    assert(n >= 3);          // 至少 3 个点才能构成一段有意义的三次样条
    xs = X;

    // 计算每段区间长度
    std::vector<double> h(n - 1);
    for (int i = 0; i < n - 1; i++) h[i] = X[i + 1] - X[i];

    // 组装三对角系统（未知数是二阶导数 M[0..n-1]）
    std::vector<double> lo(n), diag(n), up(n), rhs(n);

    // 自然边界条件：M0 = 0
    diag[0] = 1.0; up[0] = 0.0; rhs[0] = 0.0;
    // 自然边界条件：M_{n-1} = 0
    diag[n-1] = 1.0; lo[n-1] = 0.0; rhs[n-1] = 0.0;

    // 内部节点：h[i-1]*M[i-1] + 2(h[i-1]+h[i])*M[i] + h[i]*M[i+1] = 6*斜率差
    for (int i = 1; i < n - 1; i++) {
        lo[i]   = h[i - 1];
        diag[i] = 2.0 * (h[i - 1] + h[i]);
        up[i]   = h[i];
        double dy1 = (Y[i+1] - Y[i]) / h[i];
        double dy0 = (Y[i] - Y[i-1]) / h[i-1];
        rhs[i] = 6.0 * (dy1 - dy0);
    }

    std::vector<double> M = thomasSolve(lo, diag, up, rhs);
    // ... 重建系数（见 4.3）
}
```

**`diag[0] = 1.0; rhs[0] = 0.0` 是什么意思？** 这里的第 0 行方程是 `1·M_0 = 0`，即 `M_0 = 0`，正是自然边界条件"左端二阶导数为零"的直接编码。同理最后一行编码 `M_{n-1} = 0`。

**为什么 `diag[i] = 2(h_{i-1}+h_i)`？** 这是 2.6 节推导出的对角线系数。用 `2` 是因为一阶导数连续条件的代数整理会产生因子 2（源于二次项求导的 `2c_i`）。

**为什么 `rhs[i] = 6(dy1 - dy0)`？** 右侧是"左右平均斜率之差乘以 6"。因子 6 同样来自代数的合并。

**为什么 `assert(n >= 3)`？** 少于 3 个点无法构造有内部节点的三对角系统（内部循环 `for i=1..n-2` 会空转，且至少需要一段区间）。

### 4.3 重建每段系数

```cpp
a.resize(n - 1); b.resize(n - 1); c.resize(n - 1); d.resize(n - 1);
for (int i = 0; i < n - 1; i++) {
    a[i] = Y[i];
    b[i] = (Y[i+1] - Y[i]) / h[i] - h[i] * (2.0*M[i] + M[i+1]) / 6.0;
    c[i] = M[i] / 2.0;
    d[i] = (M[i+1] - M[i]) / (6.0 * h[i]);
}
```

这四行是 2.5 节推导结果的直接翻译：

- `a[i] = Y[i]`：左端点函数值。
- `c[i] = M[i] / 2.0`：左端点二阶导数的一半（`2c_i = M_i`）。
- `d[i] = (M[i+1]-M[i])/(6h[i])`：二阶导数的斜率除以 6。
- `b[i]`：平均斜率 `(Y[i+1]-Y[i])/h[i]` 减去曲率修正项 `h[i](2M[i]+M[i+1])/6`。

**为什么 `b[i]` 是"减"而不是"加"？** 这是最容易写错的地方之一。曲率（正二阶导数）会让曲线"向上凸"，而平均斜率是"直线连接"的斜率。当曲线向上凸时，某一点的实际切线斜率通常**小于**两点间平均斜率（对凸函数而言），因此需要"减去"曲率修正项。符号搞反会导致曲线完全错位。本文的踩坑实录会记录一个与符号相关的排查思路（虽然最终 Bug 不在符号，但这个易错点必须标注）。

### 4.4 求值

```cpp
double eval(double x) const {
    // 处理越界：钳制到定义域端点
    if (x <= xs[0])     x = xs[0];
    if (x >= xs.back()) x = xs.back();

    // 二分定位所在分段
    int i = (int)(std::upper_bound(xs.begin(), xs.end(), x) - xs.begin()) - 1;
    if (i < 0)     i = 0;
    if (i >= (int)a.size()) i = (int)a.size() - 1;

    double t = x - xs[i];
    return a[i] + b[i]*t + c[i]*t*t + d[i]*t*t*t;
}
```

**为什么用 `upper_bound` 而不是 `lower_bound`？** `upper_bound(x)` 返回第一个 `> x` 的元素下标，减 1 之后得到的是**最后一个 `≤ x` 的元素下标**，正好是左端点 `i` 使得 `x ∈ [xs_i, xs_{i+1})`。而 `lower_bound` 会在 `x` 恰好等于某个节点时返回"当前节点"而非"左段"，导致端点求值错位。

**为什么末尾还要 `if (i >= a.size())` 防御？** 当 `x == xs.back()` 时，`upper_bound` 返回 `n`，减 1 得 `n-1`，但分段只有 `n-1` 个（下标 `0..n-2`），`i = n-1` 会越界。虽然前面已经把 `x >= xs.back()` 钳制为 `x = xs.back()`，但此时 `upper_bound` 对等于末尾的值仍返回 `n`，所以仍需要把 `i` 收回到 `n-2`。这是一个**非常隐蔽的越界风险**，必须在代码里显式处理。

### 4.5 全局多项式插值（对照用）

```cpp
struct LagrangeInterp {
    std::vector<double> xs, ys;
    void build(const std::vector<double>& X, const std::vector<double>& Y) { xs = X; ys = Y; }
    double eval(double x) const {
        double r = 0.0;
        int n = (int)xs.size();
        for (int i = 0; i < n; i++) {
            double term = ys[i];
            for (int j = 0; j < n; j++) {
                if (j == i) continue;
                term *= (x - xs[j]) / (xs[i] - xs[j]);  // 拉格朗日基函数
            }
            r += term;
        }
        return r;
    }
};
```

这是标准的 **Lagrange 插值**，`O(n²)` 求值。它存在的唯一目的是**做对照组**——用最直观的方式展示全局多项式在等距节点下的 Runge 震荡有多严重，从而反衬样条插值的优越性。

### 4.6 误差量化

```cpp
struct Stats { double maxErr, rmse, meanAbs; };

Stats quantify(const std::function<double(double)>& interp,
               const std::function<double(double>& f,
               double lo, double hi, int samples) {
    double maxErr = 0.0, sumSq = 0.0, sumAbs = 0.0;
    for (int k = 0; k <= samples; k++) {
        double x = lo + (hi - lo) * k / samples;
        double e = std::fabs(interp(x) - f(x));
        maxErr = std::max(maxErr, e);
        sumSq += e * e;
        sumAbs += e;
    }
    int n = samples + 1;
    return { maxErr, std::sqrt(sumSq / n), sumAbs / n };
}
```

`quantify` 在 `[lo, hi]` 上取 `samples+1` 个密集采样点，计算三项指标：

- **max-err（最大绝对误差）**：最坏情况误差，衡量"最差点偏离多远"。
- **RMSE（均方根误差）**：整体误差水平的平方平均开根，比最大误差更能反映"典型"偏差。
- **mean-abs（平均绝对误差）**：误差绝对值的简单平均。

**为什么用三项指标而不是只看一项？** 最大误差可能被个别离群点"带偏"（比如 Runge 振荡在端点处的尖峰），而 RMSE 和均值能反映整体的拟合质量。三者结合才能全面刻画插值器的表现。

### 4.7 收敛阶测量

在 Test 3 中，我们对 `e^x` 分别用 4、8、16 个节点构造样条，记录各自的 `max-err`，然后用公式估算收敛阶：

```cpp
double order = std::log(maxErrs[0] / maxErrs[2]) / std::log((16.0 - 1) / (4.0 - 1));
```

**为什么这么算？** 假设误差满足 `E(N) ≈ C · h^p = C · (1/(N-1))^p`，则

```
E(N1)/E(N2) = (h1/h2)^p = ((N2-1)/(N1-1))^p
```

两边取对数即可解出 `p`。用 N=4 和 N=16 这两端最远的点来估计，能减少数值噪声的影响。

## ⑤ 踩坑实录

这一节如实记录开发过程中遇到的实际 Bug，每一个都遵循"症状 → 错误假设 → 真实原因 → 修复方式"的结构，让读者能避开同样的坑。

### 坑 1：`const` 引用形参被赋值 → 编译失败

**症状**：第一次编译报错

```
error: assignment of read-only location '(& b)->std::vector<double>::operator[](...)'
   26 |         b[i] -= m * cp[i - 1];
```

**错误假设**：我以为 `const std::vector<double>& b` 只是"传引用避免拷贝"，在函数体内可以像普通局部变量一样原地修改。

**真实原因**：`const&` 的语义是"只读引用"。C++ 里对 `const` 引用的底层元素做赋值，等于修改只读位置，编译器直接拒绝。Thomas 算法的前向消去偏偏需要**原地**更新对角线 `b[i]` 和右侧 `d[i]`。

**修复方式**：在函数开头拷贝一份可变的局部副本 `std::vector<double> bp = b, cp = c, dp = d;`，后续消元全部操作 `bp/cp/dp`，既不动传入参数，又满足原地修改的需求。**教训**：凡是需要"原地修改输入"的算法，要么用非 const 引用传参，要么在函数内先拷贝一份。

### 坑 2：把"自然边界"错当成"精确重现任意三次多项式"

**症状**：我的 Test 4 最初写的是"用自然样条插值 `f(x)=x³`，期望精确重现"，结果实测 `max-err = 1.84e-2`，完全失败。我一度怀疑是三对角系统或系数重建有 Bug。

**错误假设**：我错误地认为"三次样条既然是分段三次多项式，那么给定任何三次函数的采样点，就应该精确重建它"。

**真实原因**：这个直觉**只对夹紧样条成立**。自然样条强制两端二阶导数为零：`S''(0) = S''(1) = 0`。但 `f(x)=x³` 在 `x=1` 处的真实二阶导数是 `f''(1) = 6 ≠ 0`。自然边界条件强迫样条在右端点"不弯曲"，而真实的 `x³` 在右端明明是在"剧烈弯曲"，于是样条被迫在末端偏离真实函数，误差以 O(h²) 量级向内传播。这不是 Bug，而是自然边界条件应有的行为！

**修复方式**：修正测试的预期——改为验证**线性函数** `f(x)=2x+1` 能被精确重现（因为线性函数二阶导数处处为零，自然边界条件恰好是"正确的"），并且额外验证"节点处插值精确"（所有采样点必须被严格命中）。这两项都通过后，才能确认算法真的正确。**教训**：测试的预期必须与所选边界条件的理论性质一致，否则会把"正确实现"误判为"有 Bug"。

### 坑 3：收敛阶"理论"与"实测"对不上，差点误判

**症状**：Test 3 对 `e^x` 测出的收敛阶是 **2.01**，但我一开始在测试里写的是"期望 ~4（理论 O(h⁴)）"，导致测试 FAIL。

**错误假设**：我把教材上"三次样条 O(h⁴) 收敛"的结论直接套到了自然样条头上，以为所有三次样条都是四阶收敛。

**真实原因**：O(h⁴) 收敛是**夹紧样条（clamped spline）**的结论。**自然样条（natural spline）** 因为自然边界条件引入了 O(h²) 的边界误差，全局收敛阶只有 O(h²)。实测 2.01 与理论 O(h²) **完美吻合**，恰恰证明了实现是正确的。

**修复方式**：把测试预期改为 O(h²)，并同时收敛阶落在 [1.5, 3.0] 区间判定 PASS。**教训**：收敛阶是"边界条件敏感"的——同一个三次样条，换了边界条件，收敛阶就变了。写数值验证时必须精确知道自己在验证的是哪种边界条件。

### 坑 4：`upper_bound` 在端点 `x == xs.back()` 时的越界风险

**症状**（潜在）：如果不在 `eval` 里加越界防御，当 `x` 恰好等于最后一个节点时，`upper_bound` 返回 `n`，减 1 得 `n-1`，而分段数组只有 `n-1` 个元素（下标 `0..n-2`），访问 `a[n-1]` 会数组越界。

**错误假设**：我最初以为开头把 `x >= xs.back()` 钳制为 `x = xs.back()` 之后，`upper_bound` 就会安全地返回 `n-1` 或更小。

**真实原因**：`upper_bound` 的语义是返回"第一个严格大于 `x` 的元素"。当 `x` 已经等于末尾 `xs.back()` 时，`xs[n-1]` 并不大于 `x`（等于），所以 `upper_bound` 会返回 `n`（即 end 迭代器），减 1 得到 `n-1`，仍然越界。

**修复方式**：显式加 `if (i >= (int)a.size()) i = (int)a.size() - 1;` 把下标收回到最后一个有效分段。**教训**：二分查找在**闭区间端点**上的行为常常和直觉相反，边界值必须单独测试（用 `x == min` 和 `x == max` 两个极端值各测一次）。

### 坑 5：`b_i` 符号方向易错

**症状**（易错点，非本项目的实际 Bug）：在写系数重建代码时，`b_i` 的曲率修正项到底是"加"还是"减"非常容易记反。

**错误假设**：直觉上"曲率应该让斜率变大"，所以想把修正项加上去。

**真实原因**：对于上凸（二阶导为正）的函数，在区间内的平均斜率大于端点处的实际切线斜率（凸函数割线斜率介于两端切线斜率之间、且大于下端点切线斜率）。要让样条的斜率正确匹配，需要**减去**曲率的贡献。符号一旦反了，整条曲线会在所有内部段集体"翘起"或"下坠"，误差巨大。

**修复方式**：用线性函数做"退化测试"——线性函数二阶导数为零，`b_i` 退化为纯平均斜率 `(y_{i+1}-y_i)/h_i`。如果这条通过了，说明符号和系数在"曲率为零"的特例下是对的，再逐步引入曲率验证。**教训**：复杂的修正项公式，务必先做退化特例的验算。

### 6.2 关键数据解读

**（1）Runge 现象对照（Test 2）——样条完胜多项式 87.2 倍**

在等距 11 节点下拟合 Runge 函数 `f(x)=1/(1+25x²)`：

| 方法 | max-err | RMSE |
|------|---------|------|
| 自然三次样条 | **2.20e-02** | **7.16e-03** |
| 全局多项式(Lagrange) | 1.916 | 0.580 |

样条的最大误差比多项式**小了约 87 倍**（1.916 / 0.022 = 87.2）。这里多边形的 `max-err = 1.916` 已经**超过了函数值域**（Runge 函数值域是 `(0, 1]`），说明多项式在区间两端确实"冲破了物理边界"剧烈震荡——这正是 Runge 现象的典型数值指纹。而样条的最大误差仅有 0.022，只占函数最大值的 2% 左右，平滑且可控。

**（2）收敛阶验证（Test 3）——实测 2.01，与理论 O(h²) 吻合**

对 `e^x` 在 `[0,1]` 上逐步加密节点：

| 节点数 N | 区间 h | max-err | 相邻误差比 |
|----------|--------|---------|-----------|
| 4 | 1/3 ≈ 0.333 | 1.505e-02 | — |
| 8 | 1/7 ≈ 0.143 | 2.717e-03 | 5.54x |
| 16 | 1/15 ≈ 0.067 | 5.928e-04 | 4.58x |

当 h 减半时，误差约降为原来的 1/4（即 `2²` 倍），收敛阶 `p = log(1.505e-2/5.928e-4)/log(15/3) = 2.01`，与自然样条 O(h²) 的理论**精确一致**。这反过来证明了实现没有隐藏的恒定错误——如果系数或系统组装有 Bug，收敛阶通常会崩掉，无法达到 2。

**（3）退化特例验证（Test 4）——数值精确到机器精度**

- **线性函数 `f(x)=2x+1`**：max-err = `8.88e-16`，接近双精度浮点数的机器精度（`1e-16` 量级），说明线性函数被**精确**重现（线性函数二阶导数处处为 0，自然边界条件恰好是正确的，样条退化为直线段拼接，而直线段的拼接本身就是原函数）。
- **节点插值精确性**：对 `f(x)=x³` 的 7 个采样节点，样条在每个节点处的误差严格为 `0.000000e+00`，证明样条**精确穿过所有给定数据点**（这是插值的基本契约，必须逐点验证，不能只看整体 RMSE）。

**（4）光滑函数拟合（Test 1）**

对 `sin(x)` 在 `[0, 2π]` 上仅用 8 个节点，最大误差仅 `2.0e-03`。考虑到区间跨度约 6.28、平均分段长度约 0.9，这个误差水平（约 0.2% 量级）在"只用 8 个点重建一个振荡周期"的前提下是相当优秀的，而且随着节点加密会按 O(h²) 快速下降。

### 6.3 时间复杂度实测佐证

程序对 16 节点的样条构造 + 4001 点密集采样验证，总运行时间远低于 1 秒（没有可感知的卡顿）。这印证了 `O(n)` 的构造 + `O(log n)` 的单点求值 + `O(m·log n)` 的批量验证复杂度。对比全局多项式插值的 `O(n²)` 求值（且数值不稳定），样条在效率和稳定性上都是碾压级的。

## ⑦ 总结与延伸

### 技术局限性

1. **自然边界条件的 O(h²) 局限**：自然样条的全局收敛阶只有 O(h²)，当真实函数在端点处的二阶导数明显非零时，边界误差会显著拖累精度。如果能够获得端点导数信息，应改用**夹紧样条**把精度提升到 O(h⁴)。

2. **不保证"保形性"（monotonicity/shape-preserving）**：自然样条可能在某些数据下产生**过冲**（overshoot）——即使数据点本身是单调的，插值曲线也可能在相邻两点之间产生略微的隆起。对于必须严格单调或严格非负的场景（如金融利率曲线、密度场），需要配合**保单调样条（monotone spline）**或 **PCHIP（分段三次 Hermite 插值）**。

3. **要求数据点横坐标严格递增**：三次样条的构造前提是 `x_0 < x_1 < ... < x_{n-1}`。如果出现重复横坐标或者乱序输入，会导致区间长度 `h_i` 出现零值或负值，使三对角系统退化甚至除零。工程实现中必须做输入校验。

4. **外推能力弱**：样条只在拟合区间 `[x_0, x_{n-1}]` 内有意义，区间外我们只是简单地把自变量钳制到端点（等价于端点处的常数延拓）。任何向区间外的**外推**都需要额外的模型假设。

### 可继续优化的方向

1. **实现夹紧样条（Clamped Spline）**：给定端点导数 `f'(x_0), f'(x_{n-1})`，只需要改动三对角系统的首末两行，即可把收敛阶从 O(h²) 提升到 O(h⁴)。这是最直接的强化。

2. **引入调参边界（tension / smoothing spline）**：在目标函数中加入"平滑度惩罚项"（如对二阶导数的积分罚项），得到**光滑样条（smoothing spline）**，用于"有噪声数据"的拟合（此时不再要求严格插值，而是折中拟合精度与平滑度）。

3. **扩展到三维/曲面**：三次样条的思路可以推广到**双三次样条曲面（bicubic spline surface）**，即两个方向各做一次三次样条，用于图像重采样、地形建模、CAD 曲面等。这需要引入张量积结构和二维的三对角系统求解。

4. **与 B 样条/NURBS 的衔接**：本文的三次样条是"插值样条"（穿过所有点）。工业 CAD 更常用的是**近似样条**——B 样条、NURBS（本系列 08-15 已实现 NURBS 曲线），它们通过控制点而非插值点定义曲线，支持局部编辑。理解本文的"以二阶导数为未知数 + 三对角求解"思路，是理解 B 样条 de Boor 算法的良好铺垫。

### 与本系列其它文章的关联

- **08-15 NURBS 曲线渲染器**：本文的插值样条与 NURBS 的"近似 + 控制点"思路形成互补，两者共享"分段多项式 + 参数化"的底层思想。
- **10-02 动态规划 / 09-05 编辑距离**：都与"分段/子问题 + 递推求解"的算法思想相通，只是本文的递推体现在三对角线性系统的消元上。
- **02-22 Bezier 曲线 / 03-02 B-spline**：本文的 Bernstein/B-spline 家族的"插值版"对应物，读者可对照理解"插值"与"近似"两条曲线设计路线的差异。

### 一句话总结

自然三次样条插值用 **O(n) 的 Thomas 算法 + 三对角系统**，换来了 **C² 连续 + 彻底免疫 Runge 现象** 的分段光滑曲线，是离散采样点重建连续函数这一基础问题的经典、可靠、工程化的答案。
